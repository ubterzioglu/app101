Play Console kişisel hesabını aç

Tek seferlik kayıt ücreti ödenir.

  1. https://play.google.com/console/signup adresine Google hesabınla gir
  2. Hesap tipi: Personal / Kişisel seç Organizasyon seçme — D-U-N-S numarası ve kurumsal doğrulama ister.
  3. Google Payments profilini bağla veya yeni kişisel profil oluştur Yasal ad ve adresi kimlik belgenle uyumlu yaz.
  4. Tek seferlik geliştirici kayıt ücretini öde
  5. Google doğrulama isterse kimlik belgeni yükle
  6. Contact email + contact phone doğrula Google SMS veya sesli arama ile 6 haneli kod gönderir.
  7. Mağazada görünecek geliştirici e-postasını ayrıca doğrula

EAS · ~30 dk · sıradaki adımın bu

EAS kurulumu + ortam değişkenleri

Cloud build sırasında .env.local Git dışında kaldığı için uygulamanın ihtiyaç duyduğu üç public değer EAS Environment'tan okunur. Bunu yapmazsan build çalışır ama uygulama içerik çekemez.

4a — EAS CLI kur ve giriş yap

npm install --global eas-cli
eas login
eas whoami   # kullanıcı adını görmelisin

4b — Üç değişkeni ortamlara tanımla

Gerçek değerler .secret dosyanda. <DEGER> kısımlarını oradan kopyala. Komutları repo kökünde PowerShell'de çalıştır.

# PRODUCTION (zorunlu — mağaza buildi bunu kullanır)
eas env:create --name EXPO_PUBLIC_SUPABASE_URL --value "<DEGER>" --environment production --visibility plaintext
eas env:create --name EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY --value "<DEGER>" --environment production --visibility plaintext
eas env:create --name EXPO_PUBLIC_WEB_API_BASE_URL --value "<DEGER>" --environment production --visibility plaintext

# PREVIEW (zorunlu — telefon test APK'sı bunu kullanır)
eas env:create --name EXPO_PUBLIC_SUPABASE_URL --value "<DEGER>" --environment preview --visibility plaintext
eas env:create --name EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY --value "<DEGER>" --environment preview --visibility plaintext
eas env:create --name EXPO_PUBLIC_WEB_API_BASE_URL --value "<DEGER>" --environment preview --visibility plaintext

# DEVELOPMENT (opsiyonel — dev client buildi alırsan)
eas env:create --name EXPO_PUBLIC_SUPABASE_URL --value "<DEGER>" --environment development --visibility plaintext
eas env:create --name EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY --value "<DEGER>" --environment development --visibility plaintext
eas env:create --name EXPO_PUBLIC_WEB_API_BASE_URL --value "<DEGER>" --environment development --visibility plaintext

4c — Doğrula

eas env:list --environment production
eas env:list --environment preview   # her ikisinde de 3 değişken görünmeli
⛔Asla EXPO_PUBLIC_* olarak tanımlama: SUPABASE_SERVICE_ROLE_KEY · SUPABASE_SECRET_KEY · ADMIN_PANEL_PASSWORD · IP_HASH_SALT · GOOGLE_PLACES_API_KEY · service-account JSON. EXPO_PUBLIC_ ile başlayan her şey uygulama bundle'ından okunabilir. Buradaki üç değer bilinçli olarak public'tir (publishable key + RLS modeli).
💡Yerelde aynı işi npm run env:sync yapar (.secret → .env.local, yalnızca allowlist). EAS sunucusunda bu işi EAS Environment üstlenir; .env.local cloud'a hiç gitmez (.easignore engelliyor).

İlk AAB'yi Internal Testing'e manuel yükle

İlk yükleme her zaman manueldir (otomasyon sonra). Internal test zorunlu değil ama AAB'nin Play dağıtımında gerçekten çalıştığını kanıtlar — atlamanı önermem.

Release oluştur

  1. Play Console → Testing → Internal testing
  2. Create new release
  3. İlk release ise Play App Signing adımlarını onayla Google uygulamayı senin yerine imzalar; keystore yedekleme derdin olmaz.
  4. İndirdiğin .aab dosyasını yükle
  5. Release name: build sürümü kalabilir (örn. 1.0.0 (1))
  6. Türkçe release notes yaz (aşağıda hazır taslak)
  7. Save as draft → Next → error summary'deki hataları çöz
  8. Release'i internal test kanalında yayınla
almanya101 Android uygulamasının ilk test sürümü. Haberler, Türkçe hizmet rehberi, vatandaşlık testi, maaş hesaplayıcı ve iş ilanları modülleri test edilmektedir.

Kendini tester ekle

  1. Testing → Internal testing → Testers → e-posta listesi oluştur
  2. Kendi Gmail'ini (+ varsa 1–2 yakın kişiyi) ekle, feedback e-postasını gir
  3. Shareable link'i kopyala → telefonda aç → teste katıl → uygulamayı Play'den kur

Zorunlu · 14+ gün

Closed Testing — kritik 14 gün

Kişisel hesapta production için en az 12 tester, 14 gün kesintisiz opted-in kalmalı. E-posta listesine eklemek yetmez: her tester opt-in linkini açmalı, teste katılmalı, uygulamayı Play'den kurmalı ve 14 gün boyunca testten çıkmamalı.

👥Tester ayrımı: Internal testteki bir kullanıcı closed test sürümünü alamaz. Aynı kişiyi closed'da kullanmak istersen önce internal'dan çıkmalı. Pratik: internal'da sadece kendin + 1–2 kişi; closed için ayrı 15–20 kişilik liste.

Track ve tester listesi

  1. Testing → Closed testing → başlangıç track'ine gir veya yeni track oluştur Track adı önerisi: almanya101-beta
  2. Manage track → Testers → Create email list Liste adı: almanya101-closed-beta
  3. 15–20 Gmail/Workspace adresi ekle, feedback e-postası/URL'si gir
  4. Shareable opt-in bağlantısını kopyala
  5. Create new release: internal'daki AAB'yi bundle library'den seç (yeniden yüklemene gerek yok), release notes ekle, rollout'u başlat

Testerlara gönderilecek hazır mesaj

Merhaba, almanya101 Android uygulamasının kapalı test sürecine katılmak için aşağıdaki bağlantıyı Android telefonunuzda Google hesabınız açıkken açabilir misiniz? <OPT-IN-LINK> Bağlantıyı açtıktan sonra teste katılmanız ve uygulamayı Google Play üzerinden yüklemeniz gerekiyor. Önemli rica: Google Play production başvurusu için testten en az 14 gün boyunca çıkmamanız gerekiyor. Uygulamayı farklı ekranlarda deneyip gördüğünüz hataları bana iletebilirsiniz. Teşekkürler.

14 günlük takip

Her gün Testing → Closed testing → Manage track → Testers altında opted-in sayısını kontrol et. Bir tester ayrılırsa toplamın 12'nin altına düşmediğinden emin ol. Geri bildirimleri tarih/cihaz/sürüm/senaryo/sonuç kolonlarıyla kaydet — production başvurusunda Google bu süreci soracak. Hazır tablolar: docs/google-play/CLOSED_TEST_PLAN.md

⏳Bekleme süresini boşa harcama: 14 gün sayarken 10. ve 11. adımları (store listing + beyanlar) bitir. Hata düzeltip yeni AAB da yükleyebilirsin — yeter ki testerların opt-in durumu kesintiye uğramasın.

Yayın 🎉

Production release

İlk yayında kontrollü git: büyük değişiklik ekleme, stabil test buildini yayınla.

  1. Test and release → Production → Create new release
  2. Son onaylı AAB'yi bundle library'den seç (veya yeni production AAB yükle)
  3. Release notes ekle
  4. Ülke/bölge dağıtımını kontrol et
  5. Fiyatın Free olduğunu kontrol et Free yayınlanan uygulama sonradan Paid yapılamaz.
  6. App content beyanları ve store listing güncel mi bak
  7. Error summary'yi çöz → Preview and confirm → rollout'u başlat

Sonrası: opsiyonel EAS Submit otomasyonu

Sonraki sürümlerde AAB'yi elle yüklemek yerine otomatik gönderebilirsin. Google Cloud service-account JSON key gerekir:

eas credentials --platform android   # production altında Google Service Account seçeneği
eas submit --platform android --profile production
⛔Service-account JSON dosyası: repoya commit edilmez (secret taraması zaten yakalar), EXPO_PUBLIC'e konmaz, WhatsApp/herkese açık kanallarda paylaşılmaz.
